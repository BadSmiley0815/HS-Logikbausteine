1.Description

Demand-controlled operation of an air handling unit with cross-flow heat exchanger without bypass, based on indoor air quality. Good air: lots of recirculation and low fan speed to save heating energy. Bad air: outdoor air and high speed. In summer a slight exhaust surplus (“free cooling”) helps to remove heat from the hall. One instance per unit.
ID 14775 · Version 1.6
Figure 1: principle of operation.
Warning
The old time schedules for supply/exhaust speeds are obsolete. Connect O1/O2 to the fan setpoints and the schedule to I1 only.
Note
No sensor failure protection: the module uses the last value on I2–I5.

2.Operation

1. Enable

The time schedule on I1 only enables the unit.
I1 = 1: damper, fan, free cooling and temperature control active, O6 = 1.
I1 = 0: fans 0 %, outdoor and exhaust dampers 0 % (closed), recirculation damper at I23, O6 = 0.

2. Dampers by air quality

The air quality (I2) is mapped between “good” (I6) and “bad” (I7) to 0–100 % (output O10). The three dampers move linearly between their good and bad values and are limited outside the range.
Figure 2: damper position vs. air quality (defaults).

2.1 Overtemperature

If the room is more than I14 (1.0 K) above setpoint the dampers are overridden: recirculation 0 %, outdoor 100 %, exhaust 100 %. Back to automatic below I15 (0.5 K). O7 shows the state.
Figure 3: hysteresis.

3. Fans by air quality

Supply and exhaust get the same base speed, linear between I16 (good) and I17 (bad). Only the supply is then corrected by free cooling.
Figure 4: base fan speed vs. air quality.

4. Free cooling (supply reduction)

Without bypass, only the supply fan is reduced when the hall is too warm and outdoor air is cool. Exhaust stays, creating slight negative pressure; cooler outdoor air flows in through gates and leaks.

Active if: I18 (12 °C) < outdoor < room and room > setpoint.
Correction: from ΔT = room − setpoint, linear between I19 (0 K → 0 %) and I20 (5 K → I21 = 100 %).
Supply = base × (1 − correction). I22 sets a lower supply limit (0 = none).
Figure 5: correction curve and example (ΔT = 2.5 K → 50 %, 60/60 % becomes 30/60 %).

5. Air quality traffic light

O12 shows the air quality as a traffic light: 0 = green, 1 = yellow from I24, 2 = red from I25. Switching back uses hysteresis I26. Also calculated when the plant is OFF. With a falling curve (I7 < I6) the traffic light follows: lower = worse.
Figure 6: traffic light with defaults (yellow from 1000 ppm, red from 1400 ppm, hysteresis 50 ppm).

Note
DPTs are recommendations for the connected objects; the module only calculates with numbers. If the air quality sensor uses another type (e.g. 5.001 or a VOC index), set I2, I6 and I7 to the same DPT and adjust the limits.
O1–O5 always output 0–100 %; 2-byte float objects (0–10 V outputs) get the percentage directly, 5.001 works as well.
O11 (status) is longer than 14 characters and is truncated on a 14-byte object (DPT 16.000).
KNX has no dedicated traffic-light DPT; O12 is an 8-bit value (DPT 5.010): 0 = green, 1 = yellow, 2 = red.

6.Commissioning

  1. Import: Experte → Logic modules → Import → 14775_RLT_Luftqualitaet.hslz.
  2. Create iKOs via CSV import: Communication objects → Extras → Data synchronisation → Synchronise/import CSV file (carries the endpoint IDs CO@…; do not use ESF/OPC).
  3. Wire I1–I5 and O1–O6.
  4. Parameters I6–I23 as fixed values or via iKOs for adjustment in the visualisation.
  5. Check the debug page (status, ΔT); O11 shows the same text.
